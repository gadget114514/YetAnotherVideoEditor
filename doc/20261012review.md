## 2. モジュール別技術分析 (Module-by-Module Review)

### 2.1 `packages/core` (ドメインモデル・演算・コマンド)
- **主要構成**:
  - `Rational` (有理数型演算・タイムベース変換)
  - `Timeline`, `Track`, `Clip` (レイヤー構造・タイムラインモデル)
  - `CommandStack`, Undo/Redo コマンド群
  - `RenderSnapshot` (レンダラー向けイミュータブルデータ抽出)

- **長所**:
  - **BigInt による精度保証**: `Rational` の加減乗除やフレーム変換計算に `BigInt` と GCD (最大公約数) 正規化を用いており、`Number.MAX_SAFE_INTEGER` 超えや倍精度浮動小数点の丸め誤差を防止している。
  - **イミュータブル・スナップショット分離**: タイムラインから非同期レンダラーへ渡す `RenderSnapshot` が純粋データオブジェクトとして抽出されており、マルチスレッド/WebWorker 連携にも強い構造。
  - **完全な Undo/Redo 対応**: `SplitClipCommand`, `SubtitleCommands`, `SetPropertyCommands` などのコマンドパターンが徹底され、取り消し履歴が予測可能。

- **観察項目 / 潜在的課題**:
  - **`rescaleFrames` の境界値**: 丸めモード (Floor, Nearest, Ceil) の分岐は堅牢だが、極端な負の値やゼロ除算に関するユニットテストをさらに拡充するとより良い。

---

### 2.2 `packages/io` (入出力・シリアライズ・字幕パーサ)
- **主要構成**:
  - `ProjectSerializer` (`*.yave` JSON 保存・読み込み)
  - `SchemaMigration` (v1〜v3 から v4 へのスキーマ自動移行)
  - `SrtParser`, `SrtWriter`, `VttParser` (字幕ファイル入出力)

- **長所**:
  - **未知フィールドの保全 (`unknownFields`)**: 将来のスキーマ拡張や過去のレガシー設定を失わずに再保存する設計が機能している。
  - **Shift_JIS 自動判別**: 字幕ファイルのパース処理において UTF-8 と Shift_JIS のフォールバックロジックが実装されている。

- **観察項目 / 潜在的課題**:
  - **アセットパス解決のエラーハンドリング**: 不在アセットのパスリスト (`missingAssetPaths`) を返却する仕組みはあるが、UI 側での再リンク UI との連携強化が望まれる。

---

### 2.3 `packages/engine` (レンダリング・オーディオ・AI・プラグイン)
- **主要構成**:
  - `WebGlCompositor` & GLSL Shaders (合成・エフェクト・トランジション)
  - `TexturePool`, `FboPool` (GPU リソースの再利用)
  - `AudioEngine`, `AudioRenderGraph`, `DelayCompensator` (PDC 遅延補正)
  - `MediaProbe` (WebCodecs デコード連携)
  - `SubtitleRenderer`, `SubtitleEffects` (字幕アニメーション描画)
  - `AiOrchestrator` (T2V / TTS 生成およびタイムラインコミット)
  - `PluginHost` (ES Module JS プラグインのロード)

- **長所**:
  - **GPU リソース再利用機構**: `TexturePool` および `FboPool` による Ping-Pong FBO 管理により、毎フレームの GPU メモリ割り当てオーバーヘッドを大幅に削減。
  - **プラグイン・アーキテクチャ**: `IVideoFilter`, `ISubtitleEffect` インターフェースに基づき、サンプルプラグイン (`GlitchFilterPlugin`) や組み込みエフェクトの動的ロード・適用が実現されている。
  - **AI プレースホルダーフロー**: 生成待ちタスクをタイムライン上の `AiPlaceholderClip` として可視化し、完了時に自動的に `VideoClip`/`AudioClip` に昇格させる設計が優れている。

- **観察項目 / 改善推奨**:
  - **WebGL Shader Uniform ロケーションのキャッシュ**: `WebGlCompositor` 内の描画ループ (`renderFrame`) で `gl.getUniformLocation` が毎フレーム直接呼び出されている箇所がある。シェーダー初期化時に Uniform Location をオブジェクト等にキャッシュすることで、描画ループのドライバオーバーヘッドを低減可能。
  - **VideoFrame 解放漏れ防止**: WebCodecs の `VideoFrame` オブジェクトは明示的に `.close()` を呼ばない場合、ブラウザの GPU メモリを圧迫するリスクがあるため、`FrameCache` および `TextureProvider` での存続期間管理を再確認すること。

### 2.4 `packages/platform` & `apps/web` / `apps/electron`
- **主要構成**:

  - **プラットフォーム非依存設計**: ダイアログやファイル IO が `PlatformHost` 経由で抽象化されている。

## 4. 主な課題と改善提案 (Key Findings & Recommendations)

### 優先度：高 (High Priority)
1. **WebGL Uniform Location のキャッシュ化 (`WebGlCompositor.ts`)**
   - **理由**: 描画ループ内で `gl.getUniformLocation` を都度呼び出すのは WebGL ドライバー側で文字列検索が発生し、60fps 再生時のボトルネックになります。
   - **対策**: プログラムコンパイル時に Location を取得してフィールドとして保持する構文に変更する。

2. **WebCodecs `VideoFrame` & WebGL テクスチャのリソース破棄強化**
   - **理由**: 動画デコードプレビュー時、生成された `VideoFrame` の `.close()` や一時テクスチャの解放遅延が長時間再生でのメモリリークを引き起こす可能性があります。
   - **対策**: `FrameCache` の LRU 追い出し時に明示的な `VideoFrame.close()` 呼び出しが保証されているか再確認する。

3. **Playwright E2E テスト環境構築 (`tests/e2e/`)**
   - **理由**: `doc/test/test_specification.md` の仕様を全結合テストレベルで担保するため。
   - **対策**: Playwright 依存関係の導入と Web/Electron の画面起動・操作テストを追加する。

### 優先度：中 (Medium Priority)
1. **AI タスクのキャンセル処理 (`AbortController` 連携)**
   - `AiOrchestrator` の生成処理において、ユーザーがキャンセル操作を行った場合に HTTP リクエストや生成処理を停止できるよう `AbortController` / `AbortSignal` を伝播させる。

2. **ブラウザでの AudioContext 自動再生制限対応**
   - 初回ユーザー操作 (クリック等) まで `AudioContext` が suspended になるブラウザ仕様に対して、UI 上で自発的に resume を試みるアンロック通知バー等の追加。
