# YAVE テスト仕様書 (Test Specification)

本書は、YetAnotherVideoEditor (YAVE) におけるテスト戦略、テスト構成、および各単体テストの仕様について定義する。

---

## 1. テスト戦略

### 1.1 前提と方針
- **テストフレームワーク**: Qt Test (`Qt6::Test`) を使用する。
- **CI 環境での動作**: テストは GPU もメディアコーデックも搭載されていないヘッドレス環境（CI サーバー等）で実行できる必要がある。したがって、テスト用ターゲットには `yave_media` および `yave_render` をリンクせず、`yave_core`、`yave_subtitle`、`yave_audio`、`yave_io`、`yave_i18n` などの非表示ロジック層モジュールのみをリンクする。
- **再現性と決定性**: テスト内でランダム値や現在時刻などの外部状態に依存する場合は、シード固定やモック等を利用し、常に再現可能な結果を得られるようにする。

### 1.2 テストの実行方法
ビルドディレクトリ内で `ctest` コマンドを実行する。
```powershell
cmake --build build
cd build
ctest --output-on-failure
```

## 2. 単体テスト一覧と検証項目

現在実装されている、および新規追加する単体テストの仕様は以下の通りである。

### 2.1 `tst_rational` (有理数演算とフレーム数変換のテスト)
時間管理の正確性を担保するための `Rational` クラス、および秒・フレーム間の変換関数を検証する。
- **検証項目**:
  - `reduced()`: 最大公約数（GCD）による分数約分の正しさ、負の分母の正規化、ゼロ除算の保護（分母が 0 の場合は 1 にフォールバック）。
  - `comparison()`: 等価・不等価・大小比較演算子の動作。
  - `overflowComparison()`: 乗算による比較の際、`int64_t` の範囲を超えた極端な値でもクラッシュや誤判定をせず比較できること。
  - `arithmetic()`: タイムベース同士の加減算、乗算の動作。
  - `secondsToFrames()` / `framesToSeconds()`: Floor/Ceil/Nearest 各丸めモード下での秒数・フレーム数の正確な往復変換。
  - `rescaleFrames()`: 異なるタイムベース間（例: 30fps ⇄ 59.94fps）でのフレームインデックスの正確な再スケーリング。
  - `dropFrameTimebase()`: ドロップフレーム系タイムベース（23.976 / 29.97 / 59.94 fps）における往復変換の冪等性。

### 2.2 `tst_timeline` (タイムライン構造とクリップ操作のテスト)
無限レイヤー・トラック構造およびクリップの配置・削除・編集操作を検証する。
- **検証項目**:
  - トラックの動的追加・削除・順序変更に追従した Z オーダーの正確性。
  - トラック上のクリップ配置時の重複判定、自動的なイン点/アウト点のクリップ調整。
  - クリップの分割（Split）操作およびそれに伴う `QUndoStack` の状態遷移（Undo/Redo）。
  - レンダリング時に再生ヘッド位置に基づいて取得される `RenderSnapshot` （イミュータブルな描画状態のスナップショット）の生成ロジックの正確性。

### 2.3 `tst_srtparser` (字幕 SRT パーサのテスト)
外部字幕ファイル（SRT）のパース処理と、不正なファイルに対するロバスト性を検証する。
- **検証項目**:
  - 標準的な SRT フォーマットの読み込みおよび字幕区間（`SubtitleClip`）への正確な変換。
  - 複数行字幕、ルビ・フォント装飾タグ（HTMLタグ風表記）のパース。
  - タイムコード境界における丸め処理（秒からタイムラインのフレームへの変換精度）。
  - **異常系**: 不正なインデックス、空行の欠落、不正なタイムコード文字列、巨大なテキストなど、非標準的または壊れた SRT 入力時のエラー処理とクラッシュ防止。

### 2.4 `tst_projectserializer` (プロジェクト保存・JSON入出力のテスト)
プロジェクトファイル（`.yave`）の JSON 形式へのシリアライズ、およびデシリアライズを検証する。
- **検証項目**:
  - プロジェクト設定、アセットライブラリ、トラック構造、および配置済みクリップ情報の完全なシリアライズ。
  - 浮動小数点数を用いない有理数（分子/分母）による時間情報の完全な復元。
  - アセットパスがすべてプロジェクト相対パスに変換されていること。
  - 互換性のない `schemaVersion` に対するロード拒否、および移行関数による旧バージョンからのマイグレーションの正しさ。

### 2.5 `tst_delaycompensator` (オーディオ遅延補正のテスト)
エフェクトチェーンで発生する遅延を他トラックの遅延量で相殺する PDC (Plugin Delay Compensation) ロジックを検証する。
- **検証項目**:
  - 各オーディオトラックのエフェクトチェーンにおける各プラグインの申告遅延量の総和計算。
  - オーディオグラフ全体での最大レイテンシの計算と、他トラックに対して挿入すべき補正遅延サンプル数の算出。
  - スレッドセーフでロックフリーな遅延バッファへのサンプル書き込みおよび遅延出力の整合性。

### 2.6 `tst_i18n` (国際化およびタイムコードフォーマットのテスト) [新規]
ランタイムでの日本語/英語 UI 切り替え機能、およびロケール非依存のタイムコードフォーマット表示を検証する。
- **検証項目**:
  - `switchLanguageAtRuntime()`: 
    - `LanguageManager` を初期化し、言語を "en" に設定した際に英語の文字列（`Export`）が返ること。
    - 言語を "ja" に切り替えた際に、`languageChanged` シグナルが 1 回発火し、`QObject::tr` によって正しく日本語翻訳文字列（`書き出し`）が返ること。
    - 再び "en" に切り戻した際に正しく英語の文字列に戻ること。
  - `timecodeIsLocaleIndependent()`: 
    - ドイツ語ロケールなど、小数点の区切り文字がカンマ `,` になるロケールに既定ロケールを設定した状態でも、`formatTimecode` がロケールに影響されず常に `HH:MM:SS:FF` (または `HH:MM:SS;FF`) の形式を返すこと。
    - `parseTimecode` を用いて、フォーマットされたタイムコード文字列が元のフレーム数へ正しくデコードされること。

## 3. 今後のテスト計画 (AI トラック実装時)

AI トラックおよび絵コンテトラック（第13章）の実装が完了した後に、以下の追加単体テストを実装する。

| テストファイル名 | 検証内容 |
|---|---|
| `tst_cutclip` | `CutClip` のシリアライズ往復、`clone()` メソッド、`specHash` (再生成が必要かの判定ハッシュ) の一貫性と除外フィールド設定の妥当性。 |
| `tst_cutcascade` | 4 段マージ（Story Bible ⇄ カット個別上書き）の優先順位、継承元の由来判定 (provenance), `AiGenerationParams::toJson()` のパラメータ一貫性。 |
| `tst_roletrackresolver` | 冪等性（複数回解決処理を実行してもトラックやバインディングが増殖しないこと）、Z 配置の決定性、型不一致（ビデオ役割にオーディオトラックを解決等）の検出。 |
| `tst_batchdag` | 演出指示依存グラフ of 演出指示依存グラフのトポロジカルソート、循環参照の検出、`sceneBreak` による依存関係の切断、変更検知（dirtiness）の上流への再帰伝播。 |
| `tst_storyboardplan` | L1 モデル出力（絵コンテ生成計画）の JSON スキーマ検証。壊れた JSON や境界値、最大カット数上限を超えた敵対的入力に対するクランプ処理と最大剰余法による時間配分。 |
| `tst_promptcomposer` | プロンプトテンプレート展開の正確性、未知プレースホルダのスキップ、およびプロンプト書き換え後のロック陳腐化検出。 |
| `tst_selectionmodel` | ボードビューでの複数選択・削除時の依存クリップ自己修復、および `resolvedCutIds` の交差・包含判定ロジック。 |
