# 10. 国際化 (日本語 / 英語のランタイム切替)

[← 目次に戻る](../design.md)

---

## 10.1 要件

- メニュー・パネル・ダイアログの表示言語を**日本語 / 英語でランタイム切替可能**とする。
- **アプリの再読み込みを必要としない**。言語選択と同時に React の UI 全体が即座に再描画される。
- 初回アクセス時はブラウザの言語設定 (`navigator.languages`) または OS のロケールから推定し、以後は `PlatformHost.settings` に保存されたユーザー選択を優先する。
- タイムコード表記 (`HH:MM:SS:FF`) はロケールに影響されず、一貫した区切り文字を表示する。

---

## 10.2 i18next 構成

国際化フレームワークとして **i18next** および **react-i18next** を採用する。

### 10.2.1 ディレクトリ構成と Namespace

翻訳辞書は `locales/` 配下の JSON ファイルで管理し、関心事ごとに namespace を分割する。

```
locales/
├── ja/
│   ├── common.json      (OK, キャンセル, 保存, エラー等の汎用文字列)
│   ├── panels.json      (各パネルのタイトル, ツールバー, 表示設定)
│   ├── timeline.json    (トラック名, トリム, スナップ, クリップ操作)
│   ├── ai.json          (AI パネル, プロンプト, モデル選択, 生成状態)
│   └── plugins.json     (組み込みエフェクト・フィルタの表示名)
└── en/
    ├── common.json
    ├── panels.json
    ├── timeline.json
    ├── ai.json
    └── plugins.json
```

## 10.3 ランタイム切替 (`useLanguage`)

旧 Qt 版の `LanguageManager` の役割は、React Hook `useLanguage` および i18next インスタンスに置き換える。

```ts
// packages/ui/src/i18n/useLanguage.ts
import { useTranslation } from 'react-i18next';

export function useLanguage() {
  const { i18n } = useTranslation();

  const setLanguage = async (lang: 'ja' | 'en') => {
    await i18n.changeLanguage(lang);
    // PlatformHost の設定ストアへ永続化
    await window.platformHost?.settings.set('ui.language', lang);
  };

  return {
    currentLanguage: i18n.language as 'ja' | 'en',
    setLanguage,
  };
}
```

## 10.4 コーディング規約

### 10.4.1 必須ルール
1. **UI 文字列は必ず `t()` を通す**: JSX 内に直接文字列リテラルを書くことを禁止し、ESLint プラグイン `eslint-plugin-i18next` (`i18next/no-literal-string`) で静的検査する。
2. **キー命名規則**: `namespace.category.actionOrNoun` (例: `timeline.track.addVideoTrack`)。
3. **変数埋め込み**: i18next の補間構文 `{{variable}}` を使用する。文字列連結による文章の組み立ては語順の違いに対応できないため禁止する。

```tsx
// ✗ 悪い例: 文字列連結
<span>{t('timeline.selected') + count + t('timeline.clips')}</span>

// ✓ 良い例: i18next 補間
<span>{t('timeline.clipSelectedCount', { count })}</span>
```

### 10.4.2 複数形の扱い
英語の単数・複数形 (`1 clip` / `2 clips`) は、i18next の複数形サフィックス (`_one` / `_other`) で対応する。

```json
// locales/en/timeline.json
{
  "clipCount_one": "{{count}} clip",
  "clipCount_other": "{{count}} clips"
}
```

## 10.5 翻訳経路に載せない文字列

以下の文字列は国際化辞書の対象外とし、言語切替に影響されない固定値として扱う。

1. **タイムコード**: `HH:MM:SS:FF` (またはドロップフレーム時の `;FF`)。ドイツ語ロケール等で小数点が `,` になる環境でも、タイムコードは常にコロン/セミコロンで出力する。
2. **AI プロンプトと Story Bible 設定**: LLM に渡すプロンプトテンプレートや画風指定テキスト。
3. **内部 ID・JSON キー・enum 値**: `yave.filter.colorAdjust`, `mainVideo` 等。

---

## 10.6 プラグインの国際化

サードパーティ製 JS プラグインは、`yave-plugin.json` マニフェスト内でローカライズ名を提供する。

```json
{
  "name": {
    "ja": "ぼかし (ガウス)",
    "en": "Gaussian Blur"
  }
}
```

パラメータ定義 (`ParameterSchema`) の項目名も同様に多言語オブジェクトをサポートする。

---

## 10.7 フォント管理

- **UI フォント**: システム既定のシステム UI フォントスタック (`system-ui, -apple-system, "Segoe UI", sans-serif`) を使用。
- **字幕フォント**: レンダリングの一貫性を保つため、プロジェクトで使用される字幕フォントは Web Font (`FontFace` API) またはローカルフォントアクセス API を用いて明示的にロードする。

---

## 10.8 旧 Qt Linguist (`.ts`) からの移行手順

旧コードベースの `i18n/yave_ja.ts` および `yave_en.ts` に含まれる既存の日本語・英語訳文は、新アプリの実装フェーズにおいてスクリプト等で JSON 形式へ抽出し、`locales/ja/*.json` および `locales/en/*.json` へ移行する。
